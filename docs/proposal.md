# AI Slop Bench（说人话 Bench）提案

日期：2026-09-18　状态：v0.1 设计草案，尚未采集正式题集或运行模型评测。

后续工作：[50 题评测与专用改写模型实验](https://github.com/ktwu01/ai-slop-bench/issues/1)。

**先做 50 道中文写作与改写题，测模型能否遵守明确的表达要求，并保住原意。** 从写作 skills 中提取可检验的要求，给每道题配上事实清单、失败条件和适用例外。可以用确定性检查直接判失败的部分，先做扎实；自然度和交付质量另用盲评验证。

希望找到当前模型反复犯、用户反复改的问题。低通过率是一个待检验的假设，选题和评分不会以压低某个模型的分数为目标。第一版的成果是一套可复核的任务和失败案例，暂不宣称测出了通用的“人味”。

## 研究背景

前期研究区分了来源识别、语域自然度、写作质量、个人风格和 AI 腔，也指出通用 LLM judge、固定词表和单一总分的问题。下表汇总这些判断；外部研究与规则来源在本文对应段落中列出。本提案把中英各 500 题的长期设想收窄到能先完成的一版。

| 此前的诊断 | 本次的设计决定 |
|---|---|
| “像人”包含多个不同目标 | 先测指定场景下的表达约束与保真，单列自然度 |
| 通用 LLM judge 需要人工校准 | 硬规则用代码；语义保真与偏好用盲评，保留分歧 |
| 词表随模型和文体变化 | 规则、题目、提示词和模型版本分别记录；新现象进入下一版 |
| 指标容易被针对性优化 | 加入边界对照、隐藏题、机械删词基线和跨场景验证 |
| 大榜单维护成本高 | 先用 50 题验证协议，不同时建设多语言总榜和自动裁判 |

研究问题是：**把用户的表达偏好讲清楚之后，模型在完成实际任务时还会不会违约？消除这些违约，会不会损伤信息和读者体验？**

可验证指令已有 IFEval 等先例，因此“正则表达式能打分”本身不足以构成贡献。这里值得积累的是中文实际工作中的任务、规则的适用边界，以及去套话与保真之间的冲突。[IFEval 论文](https://arxiv.org/abs/2311.07911)

## 把 skill 反编译成任务

每条候选规则按下面的顺序整理：

1. 找到用户要完成的事，例如发故障说明、改周报、回复同事。
2. 从 skill 提取一个具体要求，说明它适用于什么文体、关系和渠道。
3. 编写容易诱发该问题的新材料，同时列出必须保留的事实与语义。
4. 写出一个合格答案和一个只违反目标要求的答案，验证题目可解。
5. 加入一个合理使用该表达的对照，确认检查器的适用边界。
6. 固定评分规则之后，再运行参评模型。

每道题最多设置两条主要风格约束。事实保留是所有题的共同要求。不要靠堆叠几十条禁令制造低通过率，也不要把同一句提示换 50 个话题算作 50 道题。

### 确定性判断有明确范围

| 要求 | 判定方式 | 判定能说明什么 |
|---|---|---|
| 明确禁用某个字符串或已枚举句式 | 字符串、分句扫描 | 是否遵守题目给定的禁用要求 |
| 只输出正文、不用 Markdown 标题或列表 | 格式解析 | 是否遵守输出形式 |
| 保留指定术语、命令、编号和原样引文 | 精确匹配及出现位置检查 | 指定内容是否保留，不能单独证明含义正确 |
| 是否编造承诺、把相关改成因果、丢掉条件 | 事实清单配合人工核对 | 是否改变原意或增加未经提供的信息 |
| 是否自然、礼貌、像作者本人、适合直接发送 | 场景化成对盲评 | 目标读者的判断及分歧 |

禁止某个句式时，命中即可失败。没有明确禁用时，命中只记为模式发生，不能直接判“没人味”。“不是……而是……”承担真实纠错时完全可能合适；该不该出现，必须由任务上下文决定。

关于 slop 的研究也采用分类和问题片段标注，而非把一个词当成通用质量判据。这支持本提案按问题和上下文出题的做法。[Measuring AI “Slop” in Text](https://arxiv.org/abs/2509.19163)

## 首批 50 题怎样组成

建议十个题组，每组五题：四道主要测试题，一道边界对照，共 40 道目标题、10 道对照。覆盖写消息、改现成稿、依据材料作解释，以及少量多轮修订。下表是出题配额和题目方向，尚不是可运行数据集。

| 题组 | 四道目标题的方向 | 一道边界对照 | 主要检查 |
|---|---|---|---|
| 对比套式 | 改上线通知；解释方案选择；写活动说明；改项目介绍 | 纠正会议时间时保留被否定的旧时间 | 禁式与纠错语义 |
| 开场和结尾套话 | 给查询结果；发延期消息；答配置问题；改状态更新 | 正式感谢信保留必要感谢 | 禁用开场、结尾及任务完成 |
| 用户未要求的格式 | 群聊短答；一段式解释；简短反馈；工作交接留言 | 明确要求列操作步骤 | 标题、列表、正文边界 |
| 自造词和比喻 | 改实验记录；改故障说明；写评测结论；解释资源用量 | 保留“回滚”等标准技术术语 | 指定用词及技术含义 |
| 原因和不确定性 | 原因未知；仅有相关性；样本不足；结果待复核 | 已给充分证据时允许确定判断 | 证据、因果与模态 |
| 事实与承诺 | 保留数字单位；不补截止时间；不许诺退款；不补个人经历 | 原文已有承诺时完整保留 | 事实清单与新增信息 |
| 受保护内容 | 保留命令；保留接口名；保留逐字引文；保留中英混排术语 | 引文里出现目标禁式 | 精确保留与豁免范围 |
| 读者与语域 | 同事回复；客户通知；导师邮件；朋友聊天 | 原稿已经自然时允许不改 | 场景适合度与最小改动 |
| 多轮修订 | 提醒后只给正文；加新事实后保留禁式要求；局部改稿；更换读者 | 用户明确撤销此前格式要求 | 当前有效约束与历史事实 |
| 组合与迁移 | 去套话且保数字；缩短且保条件；改语气且保术语；改结构且保立场 | 三项并列确有三项事实 | 两条风格要求与完整性 |

每组拟分三题公开、两题隐藏，总计 30/20；对照题在两个集合各五题。正式切分以来源文档和任务模板为单位，同一模板的近似改写全部放在同一侧。每组仍需编写多个独立模板。公开原型属于公开侧，不能通过换名字进入隐藏侧。

题组、规则和文体可以公开。隐藏的是实际材料、完整提示和人工参照。若没有维护隐藏集的条件，就先发布完整的 50 题诊断集，并明确它不能支持未见题泛化的结论。

## 可直接讨论的任务原型

以下答案由本提案编写，只用于说明判分，不是模型实测输出。

### 禁用对比句，同时说清上线变化

**输入**：搜索页将在周五上线，新增按作者筛选，其他功能保持原样。给同事写一条通知。只给正文，不用“不是……而是……”。

**合格示例**：搜索页周五上线，新增按作者筛选，其他功能保持原样。

**失败示例**：这次不是全面改版，而是新增按作者筛选，周五上线，其他功能保持原样。

失败示例命中禁式，硬规则失败。合格答案还需保留周五、按作者筛选和其他功能保持原样这三项信息。

### 换掉句式，保留纠错

**输入**：同事误以为会议是周三。实际定在周四 15:00，地点仍是 B201。请明确纠正日期，只给正文，不用“不是……而是……”。

**合格示例**：周三这个日期有误。会议定在周四 15:00，地点仍是 B201。

**失败示例**：会议周四 15:00 在 B201 举行。

失败示例没有禁式，但省掉了题目要求的明确纠错。它可以通过句式检查，任务仍失败。此题能直接识别“把否定半句全部删掉”的投机改写。

### 引文里的禁式有指定豁免

**输入**：校订说明文字。原通知中的以下引文必须逐字保留并只引用一次：「这不是延期，而是取消。」说明文字只需交代活动已取消，不使用该对比句式。

**合格示例**：原通知写道：「这不是延期，而是取消。」活动已取消。

评测器先确认指定引文完整且只出现一次，再对其余内容执行禁式检查。模型自己给新增句子加引号，不产生豁免。

### 少写套话，不能补承诺

**输入**：把这段改成发给客户的消息，只给正文，别增加承诺。“退款申请已收到。还在核对订单，处理时间尚未确定。我们将以高度负责的态度持续推进相关工作。”

**合格示例**：已收到退款申请，目前还在核对订单，处理时间尚未确定。

**失败示例**：已收到退款申请，我们会在三个工作日内完成退款。

失败示例更短，也没有典型套话，但新增了时间承诺。检查数字只能发现一部分问题；“尽快完成退款”之类没有数字的新增承诺也要检查。

### 限制格式时仍要完成解释

**输入**：向项目同事解释这次“回滚”的含义。材料限定为“撤回当前版本，恢复到上一个稳定版本”。用一段话，只给正文，保留“回滚”，不用标题和列表。

**合格示例**：这次回滚会撤回当前版本，恢复到上一个稳定版本。

**失败示例**：收到。

失败示例可能通过禁词和格式扫描，但没有解释任务。空回复、复述指令、无关回答也不能靠“零命中”获得任务通过。

### 该保留列表时保留列表

**输入**：把交接事项列为三个项目：备份数据库、核对版本号、通知值班同事。只给清单。

合格输出应包含完整的三个项目。此题不启用“禁列表”规则，用来发现加载去 AI 味 skill 后，模型是否连用户明确需要的格式也删掉。相同检查器不能跨题默认开启。

## 评分协议

### 三种提示条件回答三个问题

| 条件 | 模型看到什么 | 结果的解释 |
|---|---|---|
| A，日常请求 | 场景、材料与普通写作要求 | 观察默认表达习惯；未告知的禁式只报告发生率 |
| B，明确约束 | A 加本题一到两条明确表达要求 | 主评测，测指定表达要求的遵循能力 |
| C，加载 skill | B 加一个固定版本的完整 skill 包 | 对 B 做配对比较，测 skill 的增益与副作用 |

三个条件分开报告。C 每次只测一个已固定的 skill 包，并明确本题要求优先于 skill 偏好；不能事后挑最有利的 skill 结果合成一行。“请说人话”可以增加为探索条件，不进入 v0.1 主比较。

### 分数保持可解释

- **硬规则通过率**：输出非空，且本题所有启用的确定性检查通过。只统计有适用硬规则的题，按题和按规则分别报告；纯语义题的硬规则成绩记为 `N/A`，同时列出适用题数。
- **保真与完成率**：完成沟通目的；事实、条件、否定、模态和授权范围无实质增删。对照原材料由人工判断。
- **任务通过率**：输出有效，保真与完成检查通过，且所有适用的硬规则通过。统计全部题；无硬规则的题仍须通过语义检查。读起来顺但改错意思，仍判失败。
- **直接采用偏好**：给定读者和渠道，哪份更愿意直接使用，允许平局和两份都不可用。另标注自然度及问题片段。
- **对照题误伤率**：不应改动的事实、语气、格式或原文，被删去或改坏的比例。

不把这些项随意加权成一个“人话总分”。风格规则的通过率不能替代任务通过率。机械扫描的零命中也不代表自然度高。

生成主评测固定将每份候选输出与本题预先写好的人工参照配对，分别报告相对参照的胜、平、负比例；人工参照先经可接受性审核，不默认它一定更好。三次采样均保留，不临时挑选最好的一次。干预实验另按相同题目和重复序号固定 A/B、B/C 配对；改写实验则对同一原稿比较候选方案与预先选定的最佳基线。这些比较分别报告。

人工评估隐藏模型和条件标签，随机左右顺序，每对由三名熟悉该场景的中文读者独立判断；保留各自结果和问题片段。以多数票汇总，同时报告分歧率，争议题单列复核。混入少量重复题观察复标稳定性。先完成全部主评测输出的保真核对；偏好盲评若受预算限制，必须事先按题和重复序号抽样，并公开覆盖率，不外推未评输出。

LLM 可以预标问题和辅助整理。在独立的人工标注开发集上验证其表现之后，才考虑用于扩大评测规模；不得用同一模型生成、挑选并最终裁决自己的题目，也不能拿多个 LLM 一致当作人类认可。

### 检查器必须给出证据

以禁用“不是……而是……”为例，v0.1 只承诺识别已声明的字面模式：

```text
rule_id: no_bushi_ershi_v1
scope: delivered_text
normalization: NFC；统一换行；检测副本移除指定零宽字符并记录
match: 同一分句中，“不是”之后出现“而是”
boundary: 。！？!?；; 或换行
exceptions: 仅题目预先指定且完整匹配的受保护引文
evidence: 原文起止位置、命中片段、规则版本
```

这条规则不会自动覆盖所有对比表达。跨句改成“这不是升级。它是重构。”是否违约，要看题目有没有明确禁止更广的对比结构；若只有当前字面规则，就只记为待研究的变体。不能在看到输出后扩大判分口径。

规则测试需要覆盖全半角标点、插入空格、零宽字符、跨句文本、原样引文、代码和模型自行添加的引号。归一化只发生在检测副本中，并保留回到原文位置的映射；受保护代码按原文核验。

题目默认要求交付纯正文。无关解释也属于交付输出，不能由模型自行放进“说明区”获得豁免；不收集或评分内部推理过程。

每条任务记录至少包含：

```yaml
id: srh-contrast-001
family: contrast
split: public
source_rule: source-id@pinned-revision
register: colleague-message
input_facts: [上线时间为周五, 新增按作者筛选, 其他功能保持原样]
prompt_default: 按给定材料写给同事的上线通知，只给正文。
prompt_explicit: 按给定材料写给同事的上线通知，只给正文，不用“不是……而是……”。
hard_rules: [no_bushi_ershi_v1]
protected_spans: []
semantic_checks: [三个事实完整, 无新增安排或承诺]
human_reference: 搜索页周五上线，新增按作者筛选，其他功能保持原样。
```

参照答案仅证明可解，并帮助标注者核对含义；自然语言答案不做全文 exact match。正式 schema 还需记录来源授权、模板分组、异常状态和审核记录。

## 难度怎样产生，结果怎样复现

难度来自真实冲突：资料容易诱发熟悉的句式；用户要求简短但信息不能漏；改稿时要保留术语；多轮里要记住仍有效的要求。先扩出候选池，再依据真实需求、题组覆盖、人工可解和判分一致性选题。

开发阶段可以用模型寻找失败，但必须记录参与出题的模型和筛选过程。另用未参与筛题的模型检验结果。所有在试跑后调整过的题保留修改记录；正式冻结之后不因为某个模型答对就删题。若另建模型失败挖掘集，应标明它的选取方式，不拿它估计日常失败率。

最先做 12 道开发题，覆盖禁式、保真和边界对照，验证检查器和标注说明。开发题独立于正式 50 题。正式题至少有一份经人工确认的合格答案；人也无法稳定理解规则的题先修订。

主评测先跑 B 条件。建议比较至少三个模型家族的四个固定模型版本，每题独立生成三次，共 `4 × 50 × 3 = 600` 个输出。A/C 在固定预算允许时补齐；全部三种条件为 1,800 个输出。此处是实验规模建议，尚未调用模型或承诺评测费用。

重复采样不做择优，不把三次中的最好答案当成绩。置信区间按任务聚类估计，保留题组分层；同一道题的多次生成不算独立题目。公开、隐藏、目标题和对照题分项报告，不能把重复采样包装成大样本。50 题适合诊断，细小名次差异暂不作结论。

保存模型完整标识、日期、所有可控提示、参数、输出上限、skill 文件清单与哈希、原始回复和评分版本。平台不支持的采样参数如实记为不可控。固定系统提示中不得夹入本 bench 的额外写作规则。

模型主动拒答、空答或生成至长度上限却未完成任务，计任务失败；网络及服务错误标为无效运行，按预定上限重试，仍无结果时报告缺失，不能算模型的风格失败。多轮任务使用固定对话脚本，逐轮记录有效约束，最后一轮计主成绩，早期轮次用于诊断。

## 下一步可以走到专用改写模型

先比较四种干预：短提示、完整 skill、机械删词或替换、通用模型改写。机械基线尤其有用：如果它能提高规则分，却让事实和可用性变差，说明 benchmark 的保真检查不可省。

专用模型的产品任务可以定义为：输入原稿、读者、文体和必须保留的内容，输出可直接使用的改稿。训练目标包括保留好句、保留不确定性、保留真实纠错，以及在原稿已经合适时不改。单纯惩罚禁词会鼓励删信息、换套话和过度改写。

可先用独立的人工改写对做小规模 SFT，再判断是否需要偏好训练。训练集、开发集和 benchmark 按来源及模板隔离，公开题也不进入训练。规则可以成为训练反馈的一部分，保真和人工偏好需要同时约束优化。

Antislop 给出了训练减少重复表达的先例，文中也报告 DPO 在其设置下可能损伤写作质量。这支持开展小实验，尚不足以证明同样方法能解决中文场景化改写。[Antislop](https://arxiv.org/abs/2510.15061)

是否扩大训练，先看未见材料上的保真和误改结果。满足这些要求后，可以选择让更多读者愿意直接采用，也可以在质量持平时显著降低成本或时延。实验前选定目标和门槛。具体数据规模、基线和进入下一阶段的条件放在配套 GitHub issue 中。

## 第一版交付标准

- 50 条独立任务，含 10 条边界对照；每条有人类可接受答案和来源记录。
- 一套版本化规则，以及命中、未命中和豁免案例；每次失败能返回证据片段。
- 固定的生成与评分协议，能重放原始输出、复算确定性成绩。
- 一份至少覆盖三个模型家族的 B 条件结果；A/C 未完成时明确留空。
- 人工保真核对与成对盲评，公开分歧；未审核输出不得宣称任务通过。
- 分项结果、失败分析和局限说明，不预填“当前模型普遍低分”的结论。

B 条件先定位明确要求后仍存在的失败；补齐 A/C 后，再比较提示与 skill 的增益和副作用。专用模型的训练决策还需独立的改写留出集。
