# AI Slop Bench 设计

本文记录这套写作评测的设计意图与判分原则。题集当前有哪些题、各自什么版本、是否跑过模型，都在[题目目录](../examples/tasks/index.md)，不在这里重复。

**给模型正常的写作请求，观察它会不会主动写出 skills 记录的套话，再比较加入去套话提示后的变化。** 输入是题目，输出是回答正文。聊天界面、API 或 CLI 均可采样，无须 Harbor、Docker 或解题工具。

## 要回答的问题

普通写作请求会诱发哪些表达习惯？固定的去套话提示能减少多少问题？修改风格后，模型是否仍保留事实、必要否定、真实感受和适合场合的礼貌？

题面不透露评分规则，不要求识别 AI 味，也不给现成套话供模型照抄。用技能里的模式选择容易出现问题的场景，再用事实清单和合理表达对照划清边界。低通过率是待验证的假设，不能靠事后追加规则或删除答对的题来维持。

## 保留原题的版本边界

原题要求在内部周会介绍工单整理工具。用户给出一条 GPT 回答，报告未用 Harbor、未加去套话提示，但具体模型版本、完整输入与平台提示尚未核实，也没有配对 B 回答。

该回答没有 S1 对比套式；“需要特别说明的是”属 S2，“工具只负责…不会代替…也不会自动…”整体属 S3，“内容相近、属于同类问题”属 S4。完整原文和判定见[开发样本](../examples/observations/support-ticket-user-001.md)。必要的人工回复、不自动发送事实仍须保留，不能把否定词本身当成错误。

客服工具介绍题继续使用 [rubric v0.2](rubric.md) 和 [评审指令](../graders/strict-editor-v0.3.md)，题面和 B 提示不变。S5–S7 只进入 v0.3，不用新规则重标旧结果为正式测试。

## A/B 只改变风格提示

| 条件 | 模型看到什么 |
|---|---|
| A | 自然题面与两组共用的事实保留指令 |
| B | 相同内容，另加所属版本的固定风格提示 |

v0.3 的题共用[题目目录中的 v0.3 提示](../examples/tasks/index.md)。比较测量的是整段提示的效果，不能单独归因到某一句。v0.2 的题用自己的提示，跨版本结果分别报告。

两组共用模型版本、推理档位、可控生成参数、输出上限和工具设置。每次开新会话，解题上下文不含旧回答、评语、参考答案或评分规则。核查并保存可见系统与开发者指令；平台内部提示不可见时标为未知，A 只能称“未额外添加去套话提示”。不能由此推断模型训练历史。

采样步骤见[试验流程](pilot-protocol.md)。重复采样用于检查表现是否稳定，不能当成新增独立题，也不足以支持广泛的模型排名。

## 严格评分

原题查 S1–S4，新题查全 S1–S7，并分别检查有效性、事实保真和任务可用性。strict-v1 对任意一处确认问题判整份回答失败，`reward = 0`。不取平均、不给部分分，也不因其他句子写得好而抵消错误。即便已找到失败，仍须查完所有项。

| 记录 | 要求 |
|---|---|
| 表达问题 | 精确原文片段、所属规则和上下文理由；字面命中与语义判断分开 |
| 合理例外 | 指明题目或源事实为何需要该表达，不能代读者想象顾虑 |
| 事实保真 | 核对全部事实、否定、条件和范围，检查新增能力、安排与承诺 |
| 可用性 | 核对读者、目的和文体；近似字数不得变成事后设定的硬门槛 |
| 总判定 | 全项通过才给 1；确认失败给 0；无失败但有未裁定项时保留未裁定 |

[v0.3 严格评审提示](../graders/strict-editor-v0.3.md)规定新题的完整检查和 JSON 格式。[评分校验脚本](../scripts/score_review.py)同时支持 v0.2 与 v0.3，校验记录和汇总判定，不代替语义评审。

评分隐藏模型身份与 A/B 标签。保留每项证据、分歧和未裁定项，再汇总两组表现。报告总体结果时同时给出分项与事实保真结果；不能把其他类问题算作对比句命中，也不能将未裁定项默算成通过。

## 后续选题与历史材料

新题的诱发效果须由采样验证。开发阶段可以修题或修规则，但须更新版本，保留选题依据，并用新回答验证。不能把参与修改的答案再次称作独立测试。

`tasks/`、`shared/` 和旧运行脚本保留此前的明确约束实验，其 `reward` 不等同于当前语境评分。旧模型审阅和提示污染检查见 `docs/reviews/`。Harbor 可供旧实验或后续统一调度使用，不构成当前写作评测的要求。
